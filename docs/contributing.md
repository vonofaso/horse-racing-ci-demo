# Правила внесения изменений

## Порядок работы

1. Создать задачу с описанием и критериями приёмки.
2. Обновить локальную ветку main.
3. Создать отдельную ветку от main.
4. Выполнить изменение несколькими осмысленными коммитами.
5. Отправить ветку и создать Pull Request.
6. Получить проверку второго участника команды.
7. Исправить замечания отдельными коммитами.
8. Слить изменение только после успешных проверок и одобрения.

## Обязательные команды проверки

- `make verify` — Ruff, Bandit, unit- и интеграционные тесты, покрытие и 36
  обязательных мутаций; требует отдельную `TEST_DATABASE_URL`.
- `make container-check` — обязательная приёмка контейнерного окружения;
  требует работающий Docker и настроенный `.env.compose`. Не заменяет `make verify`.
  `make container-policy` выполняет только статическую часть.

После изменения контейнерной конфигурации запуск или обновление рабочего
окружения выполняется через `make up` / `make container-up`: сначала полный
`container-check`, затем рабочий `up`. Ошибка приёмки блокирует обновление.
Контейнерные запреты: [lab4-container-policy.md](lab4-container-policy.md).

## Запрещённые действия
- напрямую отправлять изменения в main;
- удалять или отключать тесты ради успешной проверки;
- отключать анализаторы, снижать порог покрытия или добавлять исключения без объяснения;
- коммитить .env, виртуальное окружение, дампы баз данных и секреты;
- самостоятельно одобрять собственный Pull Request;
- объединять в одном коммите несвязанные изменения;
- коммитить неразрешённые маркеры конфликта.

## Критические файлы
Изменения следующих файлов обязательно проверяет второй участник:
- requirements.txt;
- requirements-dev.txt;
- requirements.lock;
- Dockerfile и .dockerignore;
- compose.yaml и compose.env.example;
- ops/postgres/;
- docs/lab4-container-policy.md;
- pyproject.toml;
- .gitignore;
- app/database.py;
- tests/;
- Makefile;
- scripts/;
- .python-version.

## Приёмка изменения
Перед слиянием необходимо проверить:
- задача существует и связана с Pull Request;
- критерии задачи выполнены;
- тесты, покрытие, Ruff и Bandit проходят;
- `make container-check` проходит для контейнерных изменений;
- секреты и локальные файлы отсутствуют, включая `.env.compose`;
- документация обновлена;
- второй участник одобрил изменение;
- приложение запускается;
- контрольный HTTP-запрос работает.
